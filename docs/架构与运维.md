# 架构与运维

本文描述 SeaTunnel Control Plane 的架构、API 边界、数据库与部署要点。

## 1. 总体架构

```text
浏览器 (Angular SPA)
    │  /api/*  （开发：proxy.conf.js → :8800；生产：Nginx 反代）
    ▼
control-plane-server (Spring Boot, 127.0.0.1:8800)
    ├── 自有 REST：认证、用户、设置、任务与调度
    ├── SeatunnelProxy：/api/seatunnel/** → SeaTunnel REST API V2
    ├── 本地 Cron：按 task_schedules 触发任务提交
    └── PostgreSQL：用户 / 会话 / 设置 / 任务 / 执行历史 / 调度
            │
            ▼
      SeaTunnel Zeta Cluster (HTTP API)
```

职责划分：

| 组件 | 职责 |
| --- | --- |
| 前端 | 可视化操作、i18n、表单与轮询展示 |
| 控制面 API | 账号与权限、任务资产、调度、上游代理与列表分页增强 |
| SeaTunnel | 实际作业运行、指标、日志、资源 |
| PostgreSQL | 控制面元数据（非业务同步数据） |

## 2. 认证与权限

- Cookie：`scp_session`（HttpOnly，SameSite=Lax，TTL 约 7 天）
- 公开：`POST /api/auth/login`、`POST /api/auth/logout`
- 其余 `/api/**` 需登录
- 管理员专属：`/api/users*`、`GET/PUT /api/settings/seatunnel`
- 内置用户名 `admin`：不可改角色 / 禁用，仅可重置密码；不可再创建同名用户
- 默认种子账号：`admin` / `123456`（首次无该用户时创建）

## 3. API 分组

### 3.1 自有接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 服务标识（`mode: java-server`） |
| POST | `/api/auth/login` | 登录，写入会话 Cookie |
| POST | `/api/auth/logout` | 登出 |
| GET | `/api/auth/me` | 当前用户 |
| POST | `/api/auth/change-password` | 修改本人密码 |
| GET/POST | `/api/users` | 用户列表 / 创建（admin） |
| PUT | `/api/users/{id}` | 更新角色、启用状态或重置密码（admin） |
| GET | `/api/settings/health` | 连接健康（登录用户） |
| GET/PUT | `/api/settings/seatunnel` | SeaTunnel API Base（admin；PUT 会探测） |
| GET/POST | `/api/tasks` | 任务列表 / 创建；`?sync=false` 可关闭状态同步 |
| GET/PUT/DELETE | `/api/tasks/{id}` | 任务详情 / 更新 / 删除 |
| POST | `/api/tasks/{id}/run` | 立即提交 |
| GET | `/api/tasks/{id}/runs` | 执行历史（`page` / `rows`） |
| GET/PUT | `/api/tasks/{id}/schedule` | 调度配置 |

### 3.2 SeaTunnel 代理

前缀：`/api/seatunnel/**` → 去掉前缀后转发到已配置的 API Base。

前端常用能力包括：overview、running-jobs、finished-jobs、pending-jobs、job-info、submit-job、stop-job(s)、logs、metrics、openmetrics、system-monitoring-information、resource/workers、encrypt-config、checkpoints 等。

对 running / finished 列表，服务端可做分页封装与短时缓存，减轻上游压力。

## 4. 数据模型（PostgreSQL）

脚本位置：`control-plane-server/sql/`。

| 表 | 用途 |
| --- | --- |
| `users` | 本地账号与角色 |
| `sessions` | 登录会话 |
| `app_settings` | 键值配置（如 `seatunnel_api_base`） |
| `tasks` | 作业模板配置 |
| `task_runs` | 任务触发产生的作业记录 |
| `task_schedules` | Cron 表达式、时区、下次执行等 |

迁移策略：

- 手写 `CREATE TABLE IF NOT EXISTS`（`init.sql`）
- 运行时 JPA `hibernate.ddl-auto=update` 补齐差异
- **无** Flyway / Liquibase

注意：`application.yml` 默认 `SCP_PG_PORT=5432`，而部分 `sql/*.sql` 注释示例使用 `5360`。以实际 Postgres 端口为准，并通过环境变量对齐。

## 5. 本地开发推荐流程

1. 启动 / 确认 PostgreSQL，执行建库建表（或依赖 ddl-auto）。
2. `cd control-plane-server && mvn spring-boot:run`
3. `cd control-plane-web && npm start`
4. 浏览器打开 `http://127.0.0.1:5174/`，配置 SeaTunnel API Base。

端口冲突时：

```bash
SCP_PORT=8801 mvn spring-boot:run
SCP_PORT=8801 SCP_WEB_PORT=5175 npm start
```

## 6. 生产部署

### 6.1 后端

```bash
cd control-plane-server
./package.sh
cd package
# 按需编辑 application.yml 或用环境变量注入数据库与端口
./start.sh
```

建议：

- 使用 systemd / supervisord 等保活
- `SCP_PORT` 仅本机监听，由 Nginx 对外暴露
- 单独备份 PostgreSQL；勿把数据库放在不可靠的网络文件系统上

### 6.2 前端

```bash
cd control-plane-web
npm ci
npm run build
```

将 `dist/control-plane-web/` 交给 Nginx（或同类）静态托管。

### 6.3 反向代理示意

```nginx
server {
  listen 443 ssl;
  server_name scp.example.com;

  root /var/www/control-plane-web;
  index index.html;

  location /api/ {
    proxy_pass http://127.0.0.1:8800;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }

  location / {
    try_files $uri $uri/ /index.html;
  }
}
```

要点：Java **不**托管 Angular 静态文件；务必代理完整 `/api`（含 `/api/seatunnel`）。

## 7. 运维注意

| 主题 | 说明 |
| --- | --- |
| 单实例调度 | Cron 在 API 进程内；多副本会导致任务重复触发 |
| 默认密码 | 上线后立刻修改 `admin` 密码 |
| SeaTunnel 未配置 | 登录后健康检查失败，需在设置中填写 API Base |
| `package/application.yml` | 可能被本地改过且被 gitignore；权威默认以 `src/main/resources/application.yml` 为准 |

## 8. 排障

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 前端能开但登录 / API 失败 | 未启后端或代理端口不对 | 确认 `:8800`；检查 `SCP_PORT` 与 `proxy.conf.js` |
| 生产静态页 404 刷新 | SPA 未回退到 `index.html` | Nginx `try_files` |
| 数据库连接失败 | 端口 / 密码 / 库名不一致 | 对齐 `SCP_PG_*` 与 Postgres |
| 作业列表空但集群有作业 | API Base 错误或上游不可达 | 设置页保存探测；查服务日志 |
| 调度重复执行 | 启了多个 API 实例 | 保持单实例或后续加分布式锁 |
